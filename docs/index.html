Overview

Unblock removes ads, trackers, telemetry beacons, popups and intrusive elements using Chromium's MV3 declarativeNetRequest, heuristic cosmetic hiding, a small auditable scriptlets engine and a visual element picker.

Decisions are made locally against bundled rule lists. Unblock makes no network requests of its own and ships no remote code — the behavior you review is the behavior you get.

Designed for predictability, auditability and low overhead. This is a pragmatic subset of what a full-fledged filter browser offers, not a 1:1 port of uBlock Origin — the gaps are documented honestly in the limits section.

Features

Network Blocking

Curated DNR rule sets for ads, privacy and trackers, with resource-type targeting that leaves video streaming alone.

Element Picker

Hover, click, done. Generates safe CSS selectors and persists them as ##... custom rules.

Scriptlets

Defensive subset: no-adblocker, set-constant, json-prune, remove-attr, timer guards, no-eval-if.

Popup / New-Tab Guard

A MAIN-world guard intercepts window.open and new-tab hijacking attempts — including popunders that sit inside video players.

Whitelist & Custom Rules

One-click per-site allowlist, import/export as JSON, and raw adblock-style rules parsed into safe DNR primitives.

Privacy-First

Local-only state, no telemetry, no remote code, least-privilege permissions, MIT licensed.

Honest Limits

Manifest V3 removed several MV2-era capabilities. Unblock implements the reliable subset and says what it does not do.

Capability Unblock (MV3) Note
Per-request dynamic filtering No DNR is static; no MV2-style live allow/block UI.
Full ##+js() scriptlet set Subset Only curated, low-risk scriptlets are shipped.
removeparam= / redirect= / replace= No Not expressible with safe MV3 DNR primitives.
CNAME uncloaking No Not exposed via DNR.
Real-time request logger No MV3 lacks a live webRequest stream.
Filter list auto-updates Planned (opt-in) Rule lists ship inside the package for now.

Installation

Unblock installs from source as an unpacked MV3 extension in any Chromium browser (Chrome, Edge, Brave, …).

  1. Clone the repository: 
    git clone https://github.com/adyoi/unblock.git
  2. Open chrome://extensions/ and enable Developer mode (top-right).
  3. Click Load unpacked and select the cloned unblock folder (the one containing manifest.json).
  4. Pin the extension, make sure the icon is colored, and browse.

Prefer a packaged build? Grab the latest .zip from the releases page.

  • Manage the per-site whitelist
  • Launch the Element Picker

Element Picker

  • Hover to highlight the target box
  • Click to block the selected element
  • Block a parent element or undo in one click

Options Page

  • Custom rules: cosmetic ##, domain ||, plain paths
  • Whitelist editor with normalization
  • Import / export your configuration as JSON
  • Advanced defenses and heuristics toggles

Architecture

Network (DNR)

Four static rulesets, priority 1, resource-type aware and thirdParty-scoped. Dynamic whitelist rules use allowAllRequests on frames plus initiator-scoped allow for subresources.

Cosmetic

document_start injection with a MutationObserver, requestAnimationFrame coalescing and WeakSet deduplication. Ownership markers keep multiple hiders from corrupting each other.

Scriptlets

A defensive engine in the ISOLATED world plus a MAIN-world popup/new-tab guard that exempts only genuine media controls.

State & Messaging

js/state.js shares one snapshot of settings via chrome.storage. UI talks to the service worker over runtime messages; the picker bridges through postMessage.

Security & Privacy

  • No remote code, no telemetry, no analytics, no accounts
  • No outbound requests of the extension's own
  • All state in chrome.storage.local on your device
  • Defensive boundaries, CSS escaping, depth and length guards
  • XSS-safe DOM handling; import and rule parsing sanitized
